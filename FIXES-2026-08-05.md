## FIX 1 — success_url / cancel_url Stripe → `app.ink-flow.me`

### Fichiers modifiés

| Fichier                                                     | Changement                                                                          |
| ----------------------------------------------------------- | ----------------------------------------------------------------------------------- |
| `supabase/functions/_shared/siteUrl.ts`                     | Ajout `resolveAppBaseUrl()` : préfère `APP_URL`, fallback `https://app.ink-flow.me` |
| `supabase/functions/create-checkout-session/index.ts`       | `success_url` / `cancel_url` via `APP_URL`                                          |
| `supabase/functions/create-subscription/index.ts`           | Idem (dashboard abo)                                                                |
| `supabase/functions/create-theme-checkout-session/index.ts` | Idem (thème PRO)                                                                    |
| `supabase/functions/google-calendar-auth/index.ts`          | Redirect post-OAuth → `APP_URL/dashboard`                                           |
| `supabase/functions/google-business-auth/index.ts`          | Redirects erreur/succès → `APP_URL/dashboard`                                       |
| `.env.example`                                              | Commentaire : `APP_URL` obligatoire pour Stripe/OAuth app                           |

### Pourquoi

Les Edge Functions utilisaient `SITE_URL` avec fallback `https://ink-flow.me` (landing Framer). Les routes `/reservation-succes`, `/book`, `/dashboard` vivent sur **`app.ink-flow.me`** → 404 post-paiement si le secret prod pointait vers la landing.

### Où configurer `APP_URL`

| Environnement                              | Action requise                                                                              |
| ------------------------------------------ | ------------------------------------------------------------------------------------------- |
| **Supabase Edge Secrets** (prod)           | `npx supabase secrets set APP_URL=https://app.ink-flow.me` — **obligatoire** avant redeploy |
| **Supabase Edge Secrets** (dev local Edge) | `APP_URL=http://localhost:3000`                                                             |
| **`.env.local`** (frontend Vite)           | Optionnel : `VITE_APP_URL` — **n’alimente pas** les Edge Functions                          |
| **Vercel**                                 | Pas requis pour Stripe redirect (secrets Supabase)                                          |

### Test manuel FIX 1

1. `supabase secrets set APP_URL=https://app.ink-flow.me`
2. Redéployer les functions modifiées
3. Paiement flash test → URL finale `https://app.ink-flow.me/reservation-succes?session_id=cs_...`
4. Annuler checkout → `https://app.ink-flow.me/studio/{slug}?payment=cancelled` ou `/book/...`

## FIX 2 — Cron relance 12h (colonnes manquantes)

### Choix de conception

| Colonne audit    | Décision                                                                              |
| ---------------- | ------------------------------------------------------------------------------------- |
| `deposit_amount` | **Non ajoutée** — doublon de `deposit` (déjà rempli à la réservation)                 |
| `deposit_link`   | **Ajoutée** — URL Stripe Checkout (`session.url`) nécessaire pour l’e-mail de relance |

La requête cron ne peut pas reconstruire le lien sans appeler Stripe ; on persiste `session.url` à la création du checkout.

### Fichiers modifiés

| Fichier                                                               | Changement                                                |
| --------------------------------------------------------------------- | --------------------------------------------------------- |
| `supabase/migrations/20260805120000_add_appointment_deposit_link.sql` | Colonne `deposit_link TEXT` + index partiel               |
| `supabase/functions/create-checkout-session/index.ts`                 | Écrit `deposit_link` sur le RDV après création session    |
| `supabase/functions/remind-unpaid-deposits/index.ts`                  | Select `deposit` + `deposit_link` (plus `deposit_amount`) |
| `types/database.ts`                                                   | Type `deposit_link` sur `inkflow_appointments`            |

### RLS / cron

`remind-unpaid-deposits` utilise **service_role** → pas de blocage RLS. Le cron pg_cron appelle l’Edge Function sans JWT (`verify_jwt=false`).

### Test manuel FIX 2

1. `supabase db push` (migration `20260805120000`)
2. Redéployer `create-checkout-session` + `remind-unpaid-deposits`
3. Créer un RDV test via `/book` avec checkout (sans payer) → vérifier en SQL : `deposit_link IS NOT NULL`, `deposit_paid = false`
4. Forcer `created_at` à > 12h (SQL) ou attendre
5. Invoquer : `curl -X POST https://<project>.supabase.co/functions/v1/remind-unpaid-deposits -H "Content-Type: application/json" -d '{}'`
6. Vérifier e-mail Resend + `reminder_sent_at` renseigné

> **Note** : les RDV créés **avant** ce fix n’ont pas de `deposit_link` → ignorés par le cron jusqu’à une nouvelle session checkout.

## FIX 3 — Créneau non libéré si paiement échoue / annulé

### Fichiers modifiés

| Fichier                                               | Changement                                                            |
| ----------------------------------------------------- | --------------------------------------------------------------------- |
| `supabase/functions/_shared/abandonPublicCheckout.ts` | Helper webhook → RPC `abandon_public_checkout_appointment`            |
| `supabase/functions/stripe-webhook/index.ts`          | Handlers `checkout.session.expired` + `payment_intent.payment_failed` |
| `supabase/functions/create-checkout-session/index.ts` | `cancel_url` + `?apt=`, metadata PI pour webhook                      |
| `hooks/useBookingFlow.ts`                             | sessionStorage e-mail + abandon au retour `payment=cancelled`         |
| `pages/public/PublicStudioPagePro.tsx`                | Idem pour vitrine `/studio`                                           |

### Pourquoi

Seul l’échec de **création** de session libérait le créneau. Cancel Stripe et carte refusée laissaient un RDV `pending` bloquant le slot.

Libération via **RPC existante** `abandon_public_checkout_appointment` (DELETE atomique + vérif e-mail) — pas de `.update()` direct.

### Test manuel FIX 3

1. Redéployer `stripe-webhook` + `create-checkout-session`
2. **Cancel** : réserver un créneau → Stripe → « Retour » → URL `?payment=cancelled&apt=...` → le créneau redevient disponible dans `/book`
3. **Carte refusée** : carte test `4000...000034` → webhook `payment_intent.payment_failed` → RDV pending supprimé (vérifier logs Stripe + table `inkflow_appointments`)
4. **Session expirée** : laisser expirer une session ou simuler `checkout.session.expired` en test mode Stripe

> **Limite connue** : si la carte est refusée puis le client réussit **sur la même session Stripe** après abandon webhook, il devra reprendre une nouvelle réservation (comportement demandé pour libérer le slot immédiatement).
