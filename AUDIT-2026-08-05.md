| Vitrine flash inline    | `pages/public/PublicStudioPagePro.tsx` L456            | `deposit_amount` BDD, sinon 30 % (min 10 € / 30 € fixe)                                                                                                                    |
| Edge validation serveur | `supabase/functions/_shared/checkoutExpectedAmount.ts` | RDV : lit `inkflow_appointments.deposit` ; flash : `deposit_amount` puis 30 % (min 10 € / 30 €) — **aligné vitrine, pas le % artiste global** pour flash sans montant fixe |
| Création session        | `supabase/functions/create-checkout-session/index.ts`  | Stripe Checkout API (`mode=payment`), Connect `transfer_data[destination]`, insert `inkflow_payments` PENDING, rate limit IP                                               |

### Webhooks Stripe gérés

**Fichier unique :** `supabase/functions/stripe-webhook/index.ts` (`verify_jwt = false`, signature Stripe).

| Événement                               | Traitement                                                                                    |
| --------------------------------------- | --------------------------------------------------------------------------------------------- |
| `checkout.session.completed`            | Abo plateforme, thème, **acompte/solde Connect** via `applyPaidCheckoutDbState`, e-mails, CRM |
| `customer.subscription.created/updated` | Sync `inkflow_subscriptions`, plan, quota CSV                                                 |
| `customer.subscription.deleted`         | Downgrade studio                                                                              |
| `invoice.payment_failed`                | Log + statut abo                                                                              |
| `invoice.paid`                          | Renouvellement abo                                                                            |
| `account.updated`                       | Sync Connect `charges_enabled`                                                                |
| `payment_intent.succeeded`              | Tap to Pay / solde Terminal uniquement                                                        |
| **Autres**                              | Ack 200 sans action (`default`)                                                               |

**Non gérés (pertinents acompte)** : `checkout.session.expired`, `payment_intent.payment_failed`, `checkout.session.async_payment_failed`.

### Idempotence & robustesse webhook

- **Oui** : table `inkflow_stripe_processed_events`, insert `event.id` avant traitement (L284–312).
- **Doublon** : PK duplicate → 200 `{ duplicate: true }`, pas de double crédit.
- **Échec insert idempotence (non-dup)** : **503** → Stripe retente (bon).
- **Échec métier après insert idempotence** : catch global → **500**, mais l’événement est **déjà enregistré** → retry Stripe = duplicate → **200 sans retraitement** → **paiement Stripe OK, BDD possiblement stale** (fragile / bloquant si DB down mid-flight).
- **Webhook en retard** : compensé par `get-payment-session` (`supabase/functions/get-payment-session/index.ts`) appelé depuis `useBookingFlow` / page succès — réconciliation `applyPaidCheckoutDbState` si session payée.

### Paiement échoué / annulé — libération créneau

| Scénario                          | Comportement                                                             | Fichier                                                                     |
| --------------------------------- | ------------------------------------------------------------------------ | --------------------------------------------------------------------------- |
| Échec **création** session Stripe | RPC `abandon_public_checkout_appointment` (DELETE pending + email match) | `hooks/useBookingFlow.ts` L765–777, `lib/supabaseDashboard.ts` L961–973     |
| **Carte refusée** sur page Stripe | Aucun webhook métier ; RDV **reste pending**, créneau **bloqué**         | —                                                                           |
| **Cancel** Stripe (`cancel_url`)  | Toast vitrine uniquement ; **pas** d’abandon RDV                         | `PublicStudioPagePro.tsx` L260–263 ; `/book?payment=cancelled` **non géré** |
| Session expirée (24h)             | Non géré                                                                 | —                                                                           |
| Relance auto 36h+                 | Annulation `status=cancelled` si relances OK                             | `remind-unpaid-deposits` passe 2                                            |

**Verdict libération créneau carte refusée : incomplet / fragile.**

### Cron relance 12h

| Attendu (prompt) | Réalité                                                                                                                          |
| ---------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| Vercel cron 12h  | **Non** — `vercel.json` : seul cron `0 8 * * *` → `/api/cron/daily-brief`                                                        |
| Relance acompte  | **pg_cron** `5 * * * *` → Edge `remind-unpaid-deposits` (`supabase/migrations/20260322140000_add_reminder_sent_at_and_cron.sql`) |
| Filtre 12h       | `created_at < NOW() - 12h`, `deposit_paid=false`, `reminder_sent_at IS NULL`                                                     |
| Email            | Resend via `sendReminderEmail` dans la fonction                                                                                  |
| Push tatoueur    | **Non** dans cette fonction                                                                                                      |

**Bloquant — colonnes fantômes :** `remind-unpaid-deposits` sélectionne `deposit_link`, `deposit_amount` sur `inkflow_appointments`, mais ces colonnes **n’existent pas** dans `types/database.ts` (Row L474–511) et **aucun code** ne les écrit. Le cron ne peut pas relancer les parcours `/book` / checkout public. Seuls les RDV avec `deposit_link` peuillé manuellement en BDD seraient éligibles (aucun writer trouvé).

### `verify_jwt=false` & validation manuelle (routes paiement)

| Fonction                                        | config.toml                            | Auth réelle                                                                                                     |
| ----------------------------------------------- | -------------------------------------- | --------------------------------------------------------------------------------------------------------------- |
| `stripe-webhook`                                | `verify_jwt=false`                     | Signature Stripe ✓                                                                                              |
| `create-checkout-session`                       | **absent** (JWT passerelle par défaut) | Anon key Bearer ; **pas** `getGoTrueUser` — **intentionnel** (public) ; validation montant serveur + rate limit |
| `get-payment-session`                           | absent                                 | Public par `session_id`                                                                                         |
| `create-theme-checkout-session`                 | absent                                 | **`getGoTrueUser`** ✓                                                                                           |
| `create-subscription` / `create-portal-session` | absent                                 | JWT session tatoueur (client)                                                                                   |
| `stripe-connect-*` / `stripe-terminal`          | `verify_jwt=false`                     | JWT vérifié dans handler                                                                                        |
| `remind-unpaid-deposits`                        | `verify_jwt=false`                     | `assertCronAuthorized` (EDGE_CRON_SECRET optionnel)                                                             |

**Pas de gap JWT** sur les endpoints **volontairement publics** (checkout vitrine). Les endpoints **dashboard** (theme, abo, Connect) valident le JWT côté handler quand `verify_jwt=false`.

### Manques / fragilités / erreurs non gérées

- **`SITE_URL` fallback `https://ink-flow.me`** dans `create-checkout-session` L17–19 : `success_url`/`cancel_url` pointent la **landing Framer** alors que `/reservation-succes` et `/book` vivent sur **`app.ink-flow.me`** → risque 404 post-paiement si secret mal configuré.
- **`deposit_link` / `deposit_amount`** : schéma Edge ≠ types générés ; cron relance **non fonctionnel** en l’état.
- **Webhook fail après idempotence** : perte silencieuse possible (compenser manuellement via `get-payment-session`).
- **Pending RDV orphelins** après abandon Stripe ou carte refusée : pas de cron de purge (sauf relance cassée).
- **Flash checkout** : `checkoutExpectedAmount` ignore `depositPercentage` artiste / studio global (30 % fixe côté serveur si pas de `deposit_amount`).
- **`create-checkout-session`** absent de `config.toml` : dépend du JWT anon ; OK en prod mais non documenté explicitement.
- Pas de statut paiement **« échoué »** en BDD (`inkflow_payments` reste PENDING).

**Verdict : À corriger** (plusieurs points **Bloquants** : `SITE_URL` checkout, cron relance `deposit_link`, créneaux bloqués après cancel/refus carte).
